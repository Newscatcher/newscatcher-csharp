## 2.0.0 - 2026-04-13
* The `AggregationClient` and its associated types (`AggregationGetRequest`, `AggregationGetRequestPublishedDatePrecision`, `AggregationGetRequestSortBy`) have been removed from the SDK. Existing calls to `client.Aggregation.GetAsync()` or `client.Aggregation.PostAsync()` will no longer compile and must be removed or replaced.
* The `AuthorsGetRequest`, `BreakingNewsGetRequest`, and their associated enum types (`AuthorsGetRequestPublishedDatePrecision`, `AuthorsGetRequestSortBy`, `BreakingNewsGetRequestSortBy`) have been removed from the SDK. Consumers using these types must migrate to the equivalent POST-based request models. Update any references to these removed types and enums in your code accordingly.
* The `LatestheadlinesClient` class has been removed from the SDK, along with its associated `LatestHeadlinesGetRequest` and `LatestHeadlinesGetRequestClusteringVariable` types. Remove all references to `client.Latestheadlines.GetAsync()`, `client.Latestheadlines.PostAsync()`, and the deleted request/enum types from your code.
* The `SearchGetRequest` record, `SearchLinkClient` class (with `SearchUrlGetAsync` and `SearchUrlPostAsync` methods), and four related enum types (`SearchGetRequestClusteringVariable`, `SearchGetRequestNewsDomainType`, `SearchGetRequestPublishedDatePrecision`, `SearchGetRequestSortBy`) have been removed from the SDK. Consumers using any of these types must update their code to use the replacement search API surfaces.
* The `SearchsimilarClient` and all associated public types (`SearchSimilarGetRequest`, `SearchSimilarPostRequest`, `SearchSimilarGetRequestPublishedDatePrecision`, `SearchSimilarGetRequestSortBy`, and `SourcesGetRequestNewsDomainType`) have been removed from the SDK. Consumers using these types or calling `client.Searchsimilar.GetAsync()` / `client.Searchsimilar.PostAsync()` must remove those usages and migrate to an alternative approach.
* Several public types have been removed and a request class has been renamed in this release.
**Removed types:** `FailedSearchSimilarResponseDto`, `SearchSimilarResponseDto`, `SimilarArticleEntity`, `SimilarDocument`, and the `PublishedDatePrecision` enum have been deleted. Remove any references to these types from your code.
**Renamed/moved request:** `AggregationPostRequest` has been renamed to `PostAggregationCountRequest` (now in the `AggregationCount.Requests` namespace). Update all usages accordingly. The `PublishedDatePrecision` property on this request now accepts a `string?` instead of the removed enum, and `Theme`/`NotTheme` now accept `string?` instead of `OneOf<string, IEnumerable<string>>?`. A new optional `AllLinksText` property has also been added to `PostAggregationCountRequest`.
* The SDK now supports asynchronous header value resolvers (`Func<ValueTask<string>>` and `Func<Task<string>>`) via the `HeaderValue` class. JSON serialization has been extended with relaxed-escaping variants, dictionary-key support for `DateTime` and `OneOf` types, and improved handling of `Optional<>` and nullable properties. `NewscatcherApiApiException` now accepts an optional `innerException` for richer error chaining.
* Several breaking changes are included in this release to align the SDK's public API surface.
**Renamed request types:** `SearchPostRequest` is now `PostSearchRequest`; `LatestHeadlinesPostRequest` is now `PostLatestHeadlinesRequest`.
**Renamed client properties:** `Latestheadlines` → `LatestHeadlines`, `SearchLink` → `SearchByLink`, `Searchsimilar` → `SearchByLink` (merged), `Aggregation` → `AggregationCount`.
**Changed field types:** `Theme` and `NotTheme` on both request types changed from `OneOf<string, IEnumerable<string>>?` to `string?`; `PublishedDatePrecision` on `PostSearchRequest` changed from the `PublishedDatePrecision` enum to `string?`.
**New fields:** `AllLinksText` (`OneOf<string, IEnumerable<string>>?`) has been added to both `PostSearchRequest` and `PostLatestHeadlinesRequest`.
**New interfaces:** `NewscatcherApiClient` now implements `INewscatcherApiClient`, and all sub-client properties are typed as interfaces (e.g. `ISearchClient`, `ILatestHeadlinesClient`).
* Several public request record types have been renamed for consistency: `SearchGetRequest` → `GetSearchRequest`, `SearchPostRequest` → `PostSearchRequest`, `SearchUrlGetRequest` → `GetSearchByLinkRequest`, `SearchUrlPostRequest` → `PostSearchByLinkRequest`, `SourcesGetRequest` → `GetSourcesRequest`, and `SourcesPostRequest` → `PostSourcesRequest`. The `SearchClient.GetAsync` and `PostAsync` methods now return `WithRawResponseTask<T>` instead of `Task<T>` — existing callers must await the result and access `.Data` to retrieve the original response, or `.RawResponse` for HTTP metadata. A new `AllLinksText` filter parameter has also been added to `GetSearchRequest`.
* The `GetAsync` and `PostAsync` methods on `SourcesClient` and `SubscriptionClient` now return `WithRawResponseTask<T>` instead of `Task<T>`, giving consumers access to the raw HTTP status code, headers, and request URL alongside the deserialized response. Several breaking changes accompany this update: `SourcesGetRequest` has been renamed to `GetSourcesRequest`, `SourcesPostRequest` to `PostSourcesRequest`, `ArticleEntity.Content` and `BreakingNewsArticleEntity.Content` are now nullable (`string?`), `AdditionalProperties` on all response types has changed from `IDictionary<string, JsonElement>` to the new `ReadOnlyAdditionalProperties` type, and `AggregationBy` has been converted from an `enum` to a `readonly record struct` to support open-ended string values. `BreakingNewsArticleEntity.RobotsCompliant` has been removed. New fields `TitleTranslatedEn` and `ContentTranslatedEn` are available on `BreakingNewsArticleEntity`, and `AllLinksData` is available on `ArticleEntity`.
* Several breaking type changes have been introduced across the SDK.
**Enums changed to open string structs:** `ClusteringVariable`, `NewsDomainType`, and `SortBy` are no longer C# `enum` types — they are now `readonly record struct` values. Existing `switch` expressions, enum assignments, and enum comparisons will not compile. Replace `switch` statements with `if`/`else` string comparisons (e.g. `value == SortBy.Relevancy`), and use `SortBy.FromCustom("...")` to construct custom values.
**`AdditionalProperties` is now read-only:** All response types (e.g. `SearchResponseDto`, `BreakingNewsResponseDto`, `ClusterEntity`, etc.) have changed `AdditionalProperties` from `IDictionary<string, JsonElement>` to the new `ReadOnlyAdditionalProperties` type. Any code that mutated or cast this property must be updated.
**`UserInput` and `Articles` types narrowed:** Properties previously typed as `object?` or `IEnumerable<object>?` are now `Dictionary<string, object?>?` or `IEnumerable<Dictionary<string, object?>>?` on `SearchResponseDto`, `BreakingNewsResponseDto`, `ClusteredSearchResponseDto`, `FailedAggregationCountResponseDto`, `FailedAuthorsResponseDto`, `SourcesResponseDto`, and others.
* The `AdditionalProperties` property on `SubscriptionResponseDto` and `TimeFrameCount` has changed its type from `IDictionary<string, JsonElement>` to `ReadOnlyAdditionalProperties`. Code that wrote to or cast this property as a mutable dictionary will need to be updated to use the new read-only API. Additionally, the SDK no longer targets net6.0 or net7.0; consumers on those frameworks should upgrade to net8.0, net9.0, or netstandard2.0.
* The SDK now includes a new `AggregationCountClient` (accessible via `client.AggregationCount`) with `GetAsync` and `PostAsync` methods that retrieve article counts aggregated by day or hour, supporting an extensive set of search filters. A new `IAuthorsClient` interface is also introduced, providing `GetAsync` and `PostAsync` methods for searching articles by author.
* The SDK now includes support for the Authors and Breaking News endpoints via new `GetAuthorsRequest`, `GetBreakingNewsRequest`, and `IBreakingNewsClient` types. A new `Optional<T>` struct is also available for PATCH-style requests where consumers need to distinguish between an unset field and an explicitly-null field.
* The SDK now exposes raw HTTP response metadata alongside parsed response data. Consumers can call `.WithRawResponse()` on any API method's return value to access the HTTP status code, request URL, and response headers. New `AdditionalProperties` and `ReadOnlyAdditionalProperties` types are also available for working with unknown or extra JSON fields on request and response objects.
* The SDK now exposes raw HTTP response metadata through the new `RawResponse` type, which provides access to the status code, request URL, and response headers (`ResponseHeaders`). New `INewscatcherApiClient` and `ILatestHeadlinesClient` interfaces are available, making it easier to mock and test SDK clients. A high-performance, RFC 3986–compliant `QueryStringBuilder` has also been added to the core library.
* The SDK now includes three new API clients: `LatestHeadlinesClient`, `ISearchClient`, and `ISearchByLinkClient`. Each client provides `GetAsync` and `PostAsync` methods for querying news articles, with rich request models supporting filtering by language, country, source, NLP data, IPTC/IAB tags, clustering, sentiment scores, and more.
* The SDK now includes a `SearchByLinkClient` with `GetAsync` and `PostAsync` methods for searching articles by URL or ID. New `ISourcesClient` and `ISubscriptionClient` interfaces are also available, along with the `AllLinksDataItem` type representing detailed link information found in articles.
