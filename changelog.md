## 2.0.0 - 2026-04-13
* The `AggregationClient` and all associated aggregation types (`AggregationGetRequest`, `AggregationGetRequestPublishedDatePrecision`, `AggregationGetRequestSortBy`) have been removed from the SDK. Consumers using `client.Aggregation.GetAsync()` or `client.Aggregation.PostAsync()` must remove these calls, as there is no direct replacement in this version.
* Several public types used for GET-based author and breaking news searches have been removed: `AuthorsGetRequest`, `AuthorsGetRequestPublishedDatePrecision`, `AuthorsGetRequestSortBy`, `BreakingNewsGetRequest`, and `BreakingNewsGetRequestSortBy`. Any code referencing these types will fail to compile. Replace usages with the updated request models available in this version of the SDK.
* The `LatestheadlinesClient` class and its associated types (`LatestHeadlinesGetRequest` and `LatestHeadlinesGetRequestClusteringVariable`) have been removed from the SDK. Callers that use `client.Latestheadlines.GetAsync()` or `client.Latestheadlines.PostAsync()` must remove or replace those references. Please consult the updated API documentation for the current approach to retrieving latest headlines.
* The `SearchGetRequest` record and all its associated enum types (`SearchGetRequestClusteringVariable`, `SearchGetRequestNewsDomainType`, `SearchGetRequestPublishedDatePrecision`, `SearchGetRequestSortBy`) have been removed. The `SearchLinkClient` class, including its `SearchUrlGetAsync` and `SearchUrlPostAsync` methods, has also been removed. Consumers relying on these types must migrate to the equivalent POST-based request models and any replacement client surface.
* The `SearchsimilarClient` (accessible via `client.Searchsimilar`) and its associated request types (`SearchSimilarGetRequest`, `SearchSimilarPostRequest`) and enums (`SearchSimilarGetRequestPublishedDatePrecision`, `SearchSimilarGetRequestSortBy`, `SourcesGetRequestNewsDomainType`) have been removed. Callers must remove any references to `client.Searchsimilar.GetAsync()`, `client.Searchsimilar.PostAsync()`, and the deleted types to compile successfully.
* Several breaking changes have been made to public types in this release:
* The public record types `FailedSearchSimilarResponseDto`, `SearchSimilarResponseDto`, `SimilarArticleEntity`, and `SimilarDocument` have been removed. Remove any references to these types from your code.
* The `PublishedDatePrecision` enum has been removed; properties that previously used it now accept `string?`.
* `AggregationPostRequest` has been renamed to `PostAggregationCountRequest`. Update all usages to the new name.
* The `Theme` and `NotTheme` properties on the aggregation request changed from `OneOf<string, IEnumerable<string>>?` to `string?`.
* A new `AllLinksText` property (`OneOf<string, IEnumerable<string>>?`) has been added to `PostAggregationCountRequest`.
* The SDK now supports asynchronous header value resolution via `Func<ValueTask<string>>` and `Func<Task<string>>` overloads on `HeaderValue`. `NewscatcherApiApiException` now accepts an optional `innerException` parameter for richer error context. Serialization has been improved with relaxed JSON escaping support and correct handling of `Optional<T>` and nullable properties in JSON output.
* This release includes several breaking changes to the SDK's public API surface.
**Renamed client properties on `NewscatcherApiClient`:** `Latestheadlines` is now `LatestHeadlines`, `SearchLink` is now `SearchByLink`, `Searchsimilar` has been removed (use `SearchByLink`), and `Aggregation` is now `AggregationCount`. All sub-client properties are now typed as interfaces (e.g. `ILatestHeadlinesClient`), and `NewscatcherApiClient` now implements `INewscatcherApiClient`.
**Renamed request types:** `LatestHeadlinesPostRequest` is now `PostLatestHeadlinesRequest` and `SearchPostRequest` is now `PostSearchRequest`. On both types, `Theme` and `NotTheme` have changed from `OneOf<string, IEnumerable<string>>?` to `string?`; `PublishedDatePrecision` on `PostSearchRequest` has changed from the `PublishedDatePrecision` enum to `string?`. A new optional `AllLinksText` field has been added to both request types.
* Retry behavior has also been improved: the SDK now respects `Retry-After` and `X-RateLimit-Reset` response headers and applies jitter to exponential backoff delays.
* Several public request types have been renamed for consistency. Update usages as follows: `SearchGetRequest` → `GetSearchRequest`, `SearchPostRequest` → `PostSearchRequest`, `SearchUrlGetRequest` → `GetSearchByLinkRequest`, `SearchUrlPostRequest` → `PostSearchByLinkRequest`, `SourcesGetRequest` → `GetSourcesRequest`, `SourcesPostRequest` → `PostSourcesRequest`, and `SourcesGetRequestNewsDomainType` → `NewsDomainType`. The `SearchClient.GetAsync` and `PostAsync` methods now return `WithRawResponseTask<T>` instead of `Task<T>`, providing access to raw HTTP response metadata via the `.RawResponse` property and the deserialized payload via `.Data`.
* Several breaking changes have been introduced in this release:
* **Raw response access**: All client methods (`SourcesClient.GetAsync`, `SourcesClient.PostAsync`, `SubscriptionClient.GetAsync`, `SubscriptionClient.PostAsync`) now return `WithRawResponseTask<T>` instead of `Task<T>`. Callers must await the task and access `.Data` for the deserialized response, or use `.RawResponse` for HTTP metadata.
* **Request type renames**: `SourcesGetRequest` is now `GetSourcesRequest` and `SourcesPostRequest` is now `PostSourcesRequest`. Update all construction sites accordingly.
* **`AggregationBy` enum restructured**: `AggregationBy` is now a `readonly record struct` instead of an `enum`. Replace any exhaustive `switch` statements or direct enum comparisons with the new string-based value pattern (e.g., `AggregationBy.Day`).
* **`Content` field made nullable**: `ArticleEntity.Content` and `BreakingNewsArticleEntity.Content` changed from `required string` to `string?`. Remove `required` initialization assumptions and add null checks.
* **`AdditionalProperties` type changed**: All response types now expose `ReadOnlyAdditionalProperties` instead of `IDictionary<string, JsonElement>`. Update any code that mutated or cast this property.
* **New fields added**: `ArticleEntity` gains `AllLinksData`; `BreakingNewsArticleEntity` gains `TitleTranslatedEn` and `ContentTranslatedEn`; `AdditionalSourceInfo` gains `RobotsCompliant`.
* Several breaking changes have been made to response types and enum definitions in this release.
**Enum types changed to string structs:** `ClusteringVariable`, `NewsDomainType`, and `SortBy` are no longer C# `enum` types — they are now `readonly record struct` types implementing `IStringEnum`. Any existing `switch` statements, enum comparisons, or casts against these types must be updated to use the new string-based comparison API (e.g., `value == ClusteringVariable.Values.Content`).
**`AdditionalProperties` type changed:** The `AdditionalProperties` property on all response DTO types (e.g., `SearchResponseDto`, `BreakingNewsResponseDto`, etc.) has changed from `IDictionary<string, JsonElement>` to `ReadOnlyAdditionalProperties`. Code that assigned to or mutated this dictionary must be updated.
**`UserInput` and `Articles` properties narrowed:** `UserInput` has changed from `object?` to `Dictionary<string, object?>?` on multiple DTOs, and `FailedAuthorsResponseDto.Articles` changed from `IEnumerable<object>?` to `IEnumerable<Dictionary<string, object?>>?`. Callers accessing these as untyped `object` must update their code.
* The `AdditionalProperties` property on `SubscriptionResponseDto` and `TimeFrameCount` has changed type from `IDictionary<string, JsonElement>` (publicly settable) to `ReadOnlyAdditionalProperties` (read-only). Any code that wrote to or cast this property as a mutable dictionary must be updated to use the new read-only type. The property still exposes deserialized extension data from JSON responses and can be accessed by key in the same way.
* The SDK now includes a new `AggregationCountClient` (accessible via `client.AggregationCount`) with `GetAsync` and `PostAsync` methods for retrieving article counts aggregated by day or hour. A new `IAuthorsClient` interface is also introduced, exposing author-based article search via `GetAsync` and `PostAsync`.
* The SDK now exposes a new `IBreakingNewsClient` interface with `GetAsync` and `PostAsync` methods for retrieving breaking news articles, along with a new `GetAuthorsRequest` record for author-based article searches. A new `Optional<T>` struct (and supporting types `IOptional`, `OptionalExtensions`, `NullableAttribute`) is also available for PATCH-style requests where it is important to distinguish between a field being undefined versus explicitly set to null.
* The SDK now exposes raw HTTP response metadata alongside parsed API responses. Consumers can call `.WithRawResponse()` on any async API method to access the HTTP status code, request URL, and response headers via the new `RawResponse` type wrapped in `WithRawResponse<T>`. Direct `await` continues to return just the parsed data with no changes required to existing code. Additionally, new `AdditionalProperties` dictionary types allow working with untyped JSON extension fields on request and response objects.
* The SDK now exposes `RawResponse`, `ResponseHeaders`, and `HttpHeader` types, giving consumers access to HTTP status codes, URLs, and headers from API responses. New `INewscatcherApiClient` and `ILatestHeadlinesClient` interfaces have been added, making it easier to mock and test SDK usage. A new `IStringEnum` interface is also available for string-backed enum interoperability.
* The SDK now includes `LatestHeadlinesClient`, `ISearchClient`, and `ISearchByLinkClient` with `GetAsync` and `PostAsync` methods for fetching and filtering news articles. New request record types (`GetLatestHeadlinesRequest`, `GetSearchRequest`) provide comprehensive query parameter support including language, country, source, NLP data, and IPTC/IAB/custom tag filtering.
* The SDK now includes a `SearchByLinkClient` accessible via `client.SearchByLink`, supporting both GET and POST requests to search for articles by link or ID. New `ISourcesClient` and `ISubscriptionClient` interfaces have been added, along with the `AllLinksDataItem` type for representing link data in API responses.
